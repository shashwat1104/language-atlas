How it all connects.

Everything in the language industry hangs off one chain: someone with a business need pays for content to cross a language boundary. This page shows that chain, the entities that attach to it, and the database structure that will hold the whole Atlas.

On this page

The main chainEntities that attach to the chainThree example paths through the graphThe 10 linked databases

The main chain

Read it as a sentence: a client in an industry has content that needs a language service; the service runs as a workflow on tools that read and write file formats; linguists or vendors (human or machine) do the work; QA checks it; it is delivered; the job turns into revenue; and the linguistic assets it produced make the next job cheaper.

Insider view

The last arrow matters most. A translation memory, termbase and style guide built for one client are the main reason clients stay with a vendor and the main reason repeat work gets cheaper. Who owns those assets — the client, the LSP or the platform — is one of the quietest and most important commercial questions in any contract.

Three example paths through the graph

Software

SaaS company → technology → UI strings → software localization → continuous workflow → TMS + MT → JSON / XLIFF → in-country reviewer → linguistic + screenshot QA → pull request merged → subscription revenue.

Clinical

Sponsor / CRO → life sciences → patient questionnaire → linguistic validation → forward, back, reconcile, debrief → CAT + version control → DOCX / PDF → two translators + clinician → certificate → regulator submission → per-language project fee.

Media

Streaming platform → entertainment → episode → subtitling + dubbing → spotting, translation, casting, recording → subtitle editor + DAW → TTML / IMSC + WAV stems → linguist + voice actors → QC → platform ingest → per-minute revenue.
